# Запуск

## Принцип работы

После запуска Hello Guest на компьютере начинает работать локальный сервер. В окне программы отображаются адреса подключения, PIN-код и служебные сообщения. Сотрудники открывают приложение в браузере планшета или смартфона, подключённого к той же локальной сети.

Не закрывайте окно программы во время регистрации гостей: закрытие остановит сервер. Для перевода окна в фоновый режим нажмите `Enter`. Перезапуск и остановка доступны на [экране статуса](status.md).

## Загрузка и установка

Скачайте файл для своей операционной системы со [страницы выпусков GitHub](https://github.com/shnikita-cr/hello-guest/releases).

| Операционная система | Файл |
|---|---|
| Windows (x86-64) | `hello-guest-windows-amd64.exe` |
| macOS (Apple Silicon) | `hello-guest-darwin-arm64` |
| Linux (x86-64) | `hello-guest-linux-amd64` |
| Linux (ARM64) | `hello-guest-linux-arm64` |

В выпуск также входит руководство `hello-guest-manual.pdf`.

## Первый запуск

1. Создайте папку для программы, например `HelloGuest`, и поместите в неё скачанный файл.
2. Запустите программу. Не закрывайте открывшееся окно сервера.

   Операционная система может запросить разрешение на доступ программы к сети: дайте согласие, нажав «Разрешить доступ» (в Windows — в запросе брандмауэра). Без этого устройства локальной сети не смогут подключиться к серверу.

3. Найдите в окне PIN-код и адрес подключения. Пример вывода:

   ```text
   PIN: 482913
   Сервер Hello Guest запущен успешно
   Адрес подключения в браузере: https://192.168.1.42:8443
   ```

   Значения приведены для примера. На вашем компьютере PIN-код и сетевой адрес могут отличаться. Сервер может вывести несколько адресов — используйте адрес, доступный с устройства регистрации в той же локальной сети.

4. Откройте указанный адрес в браузере планшета или смартфона. Проверьте, что он совпадает с адресом из окна запущенного сервера. Программа использует самоподписанный сертификат HTTPS, поэтому браузер может запросить подтверждение исключения безопасности.
5. Введите PIN-код и нажмите «Войти». После авторизации откроется приложение.

**Если подключение не установлено:** убедитесь, что сервер работает, а компьютер и устройство регистрации подключены к одной локальной сети. Затем проверьте адрес и порт. При наличии нескольких адресов в окне сервера последовательно проверьте подходящие адреса.

**Если сервер сообщает об ошибке TLS:** завершите работу программы. Перед удалением `data/tls.crt` и `data/tls.key` сохраните резервную копию каталога `data`. После удаления указанных файлов повторно запустите сервер: он создаст новый сертификат. Устройства могут снова показать предупреждение о сертификате.

## Если страница не обновляется

После обновления программы браузер может продолжать отображать сохранённую версию приложения. В этом случае:

1. Убедитесь, что устройство подключено к серверу.
2. Проверьте, нет ли сообщения «нет связи» с количеством действий в очереди. **Не сбрасывайте данные приложения, пока очередь не опустеет:** неотправленные отметки могут быть потеряны.
3. Откройте адрес, указанный в строке «Принудительное обновление версии в браузере после перезапуска сервера» (например, `https://192.168.1.42:8443/reset`).
4. Нажмите «Сбросить сейчас», дождитесь повторной загрузки приложения и авторизуйтесь по PIN-коду.

## Обновление программы

1. Скачайте новую версию со [страницы выпусков](https://github.com/shnikita-cr/hello-guest/releases).
2. Завершите текущую регистрацию и дождитесь отправки всех действий с устройств, работающих без связи.
3. Остановите сервер кнопкой «Остановить» на [экране статуса](status.md) либо закройте окно программы.
4. Замените исполняемый файл новой версией, сохранив каталог `data`.
5. Запустите новую версию и проверьте доступность приложения и списка гостей.

Каталог `data` хранится отдельно от исполняемого файла. При обычном обновлении данные гостей, отметки и PIN-код сохраняются.

## Каталог данных

Рядом с исполняемым файлом создаётся каталог `data`:

| Путь | Содержимое |
|---|---|
| `config.json` | Настройки сервера и PIN-код |
| `state.json` | Текущее состояние: гости, отметки и события |
| `tls.crt`, `tls.key` | Сертификат HTTPS и закрытый ключ |
| `hello-guest.log` | Журнал работы при соответствующем режиме запуска |
| `imports/` | Сохранённые импортированные файлы |
| `reports/` | Сформированные отчёты |

Не удаляйте и не перемещайте каталог `data` во время работы сервера. Он содержит персональные данные и секреты доступа; ограничьте доступ к нему на компьютере.

Программа создаёт резервные копии с интервалом пять минут. Точное расположение каталога `copy-data` указывается в окне сервера. При удалении `data` во время следующего запуска будет создано новое состояние с новым PIN-кодом.

## Восстановление из резервной копии

Резервные копии каталога `data` сохраняются в виде ZIP-архивов в `copy-data`. Хранятся последние двадцать автоматических копий; дополнительную копию можно создать на [экране статуса](status.md).

Восстановление возвращает состояние на момент создания выбранной копии. Все более поздние изменения отсутствуют в архиве.

1. Остановите сервер и убедитесь, что на других устройствах нет неотправленных отметок.
2. Переименуйте текущий каталог `data` в `data-old`, чтобы сохранить исходные файлы на случай повторного восстановления.
3. Создайте новый пустой каталог `data` рядом с программой.
4. Выберите подходящий архив из `copy-data` и распакуйте **его содержимое** в новый каталог `data`, сохранив структуру файлов. Проверьте, что файлы `config.json` и `state.json` находятся непосредственно в `data`.
5. Запустите сервер. Проверьте PIN-код, список мероприятий и отметки о прибытии.

Не удаляйте `data-old`, пока восстановленные данные не будут проверены.

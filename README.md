# Hello Guest

Hello Guest — приложение для ресепшена на входе: заменяет печатную выгрузку Timepad. Импортируете список гостей, ищете человека по имени или номеру билета и отмечаете приход одним касанием. Работает без интернета: локальный сервер на компьютере, отметки со всех телефонов синхронизируются в реальном времени. Сканер читает QR-коды и штрих-коды билетов.

Данные лежат в файле-журнале `hello-guest.ndjson` в каталоге данных. Исходный файл выгрузки Timepad сохраняется в `<данные>/imports/`, отчёты — в `<данные>/reports/`. PIN выводится в консоль при первом запуске и хранится в `config.json` рядом с хешем (файл читается только владельцем) — всегда доступен на экране статуса.

## Демо

Тренировочная версия без сервера: <https://shnikita-cr.github.io/hello-guest/>, PIN `0000`. Все отметки живут в браузере (localStorage), камера и сканер работают, импорт выгрузки отключён. Собирается из `demo/build.sh`, публикуется автоматически при каждом пуше в `dev`.

## Если вы не программист: запуск шаг за шагом

1. Скачайте файл для вашей системы из [релизов](https://github.com/shnikita-cr/hello-guest/releases) — для Windows это `hello-guest-windows-amd64.exe`, для Mac — `hello-guest-darwin-arm64`, для Linux — `hello-guest-linux-amd64`.
2. Положите его в любую папку, например на рабочий стол.
3. Запустите двойным щелчком. Откроется чёрное окно с надписями — это приложение работает, его закрывать не нужно.
4. В чёрном окне написано:
   - `PIN: ...` — код, которым вы войдёте в приложение;
   - `Адрес подключения: ...` — откройте этот адрес в браузере планшета ресепшена;
   - `Сброс браузера: .../reset` — эта страница понадобится, если браузер на планшете «завис» и не обновляется (откройте её и страница перезагрузится сама).
5. Откройте адрес на планшете, введите PIN — можно работать. Если адрес не открывается, попробуйте следующий из списка: подходит тот, что из вашей сети Wi-Fi.

**Обновление версии.** Скачайте новый файл из релизов, остановите приложение (кнопка «Остановить» на экране статуса, или закройте чёрное окно), удалите старый файл, положите на его место новый и запустите снова. Все гости, отметки и PIN сохраняются — данные лежат в отдельной папке `data` рядом с программой.

## Сборка

Два способа, оба создают один файл `dist/hello-guest`:

```sh
make build         # локально на машине, нужен установленный Go
make build-docker  # через Docker-контейнер, Go не нужен
```

Дополнительно:

```sh
make test           # тесты, через Docker
make release-docker # 5 бинарников в dist/ для других ОС + SHA256SUMS, через Docker
make docker-image   # образ hello-guest:$(VERSION), тег из git describe
```

Если Go установлен, для разработки можно без сборки:

```sh
go run ./cmd/hello-guest --addr :8080
```

## Запуск

Два способа: из бинарника на машине или в Docker-контейнере.

### Из бинарника

Соберите файл любым способом из раздела «Сборка», затем:

```sh
./dist/hello-guest                # порт 80, при нехватке прав — 8080
./dist/hello-guest --addr :8080   # явный порт
./dist/hello-guest --data ./data  # каталог данных (по умолчанию ./data)
./dist/hello-guest -d             # показать PIN и адреса, уйти в фон (лог: data/hello-guest.log)
./dist/hello-guest --open         # открыть экран статуса в браузере после старта
./dist/hello-guest --backup-dir ../../copy-data  # папка бэкапов (по умолчанию, от каталога данных)
./dist/hello-guest --ip 192.168.1.10,10.0.0.5  # явные IP для баннера, через запятую (автоопределение обычно хватает)
./dist/hello-guest --version
```

### Экран статуса

`https://127.0.0.1:8443/status` — страница только с самого компьютера (PIN и
управление не попадают в локальную сеть и в тоннели). Показывает состояние
сервиса и сердцебиение, число клиентов онлайн (устройства с открытой
страницей), все адреса по HTTPS, PIN и кнопки: создать бэкап вручную,
перезапустить, остановить.

- `--open` — открыть экран сразу после старта;
- синглтон: второй запуск не поднимает второй экземпляр, а открывает экран
  уже работающего;
- извне, для администраторов не в той же сети:
  `cloudflared tunnel --url http://localhost:<порт>` — публичный HTTPS-адрес,
  камера и сканер при этом работают; экран статуса через тоннель закрыт.

### Резервные копии

Демон сам каждые 5 минут кладёт zip-архив каталога данных в `--backup-dir`
(по умолчанию `../../copy-data` относительно каталога данных). Если данные не
менялись — копия пропускается. Хранятся последние 20 архивов, старые удаляются.

При старте в консоль печатается:

```
  _   _ _____ _   _  ____
 | | | |_   _| | | |/ ___| ___ ...
PIN: 123456

Hello-Guest запущен успешно
Сертификат: ./data/tls.crt
Бэкапы каждые 5 минут: ../copy-data
Адрес подключения: https://192.168.1.42:8443
Адрес подключения: https://10.0.0.5:8443
какая сеть у вас — разработчик не знает: подходит адрес, что открывается с планшета
Сброс браузера: https://192.168.1.42:8443/reset
```

С телефона в той же сети откройте один из адресов «Адрес подключения», введите PIN; дальше всё делается касаниями.

### В Docker-контейнере

Собрать образ и запустить контейнер (данные — в папке `data/` репозитория, она в .gitignore):

```sh
make docker-image
mkdir -p data
docker run -d --name hg -p 8080:80 -v ./data:/app/data --memory=128m --cpus=0.5 hello-guest:$(git describe --tags --always)
docker logs hg   # PIN при первом запуске
```

## Первые шаги на мероприятии

1. Открыть приложение и ввести PIN.
2. Открыть вкладку **Источники** (на пустом экране есть кнопка «Загрузить выгрузку»).
3. Указать имя мероприятия и выбрать CSV-файл выгрузки Timepad.
4. Нажать **Импортировать файл**.
   - Вариант вместо файла: указать ID события Timepad и нажать **Подтянуть из Timepad**. Токен не нужен, если на сервере задана переменная окружения `TIMEPAD_TOKEN`.

После импорта откроется мероприятие с полным списком гостей. Искать гостя можно по имени, email, телефону или номеру билета; касание по строке отмечает приход, повторное — снятие. Вкладки «Участники» и «Команды» переключают вид: в командном виде видны только командные билеты, состав раскрывается касанием, отмечаются люди поимённо; там же кнопки «+ Группа» и «+ Гость». Вкладка «+ Гость» добавляет пришедшего без записи, вкладка «Статистика» показывает скорость, средний интервал, разбивку по типам билетов и командные счётчики.

Повторный импорт того же файла безопасен: уже отмеченные гости не сбрасываются, дубли по email схлопываются, составы команд и отметки людей сохраняются.

## Формат CSV

Ожидается выгрузка Timepad с такими колонками:

```
Номер заказа,Дата создания,Статус,Email,Тип билета,Номер билета,EAN,Имя,Фамилия,Телефон,Промокод,Сумма
```

Колонки распознаются без учёта регистра, по списку синонимов: «номер билета», «билет» и «номер» — одно и то же поле. Порядок колонок не важен, лишние игнорируются.

## API (кратко)

Все эндпоинты, кроме `/`, требуют заголовок `X-Pin`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/pin` | проверка PIN |
| GET | `/api/events` | список мероприятий со счётчиками |
| GET | `/api/state?event=` | все гости мероприятия |
| POST | `/api/checkin` | `{"event","guest_id","device","via"}` — отмечает гостя пришедшим; повторный вызов возвращает `already:true` и ничего не меняет |
| POST | `/api/undo` | снять отметку |
| POST | `/api/guest` | `{"event","name","phone","email","ticket_type"}` — добавляет гостя, которого нет в выгрузке (пришёл без записи); для ручной группы — ещё `team` и `members` |
| POST | `/api/member` | `{"event","guest_id","members":{...:true}}` — полный снапшот поимённых отметок прихода в группе |
| POST | `/api/team` | `{"event","guest_id","team","members":[...]}` — меняет название и состав группы |
| POST | `/api/import?event=` | тело — CSV-файл |
| POST | `/api/refresh` | `{"event","timepad_id","token"}` — загрузка данных из Timepad API |
| GET | `/api/stats?event=` | счётчики |
